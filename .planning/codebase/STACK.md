# Technology Stack

**Analysis Date:** 2026-10-30

## Languages

**Primary:**
- Python throughout `app/`, `tests/`, and the root maintenance scripts.
- The sibling environment at `../venv/pyvenv.cfg` reports Python 3.14.3; the repository does not pin an interpreter version. Treat this as an observed local environment, not a supported-version guarantee.

**Secondary:**
- SQL embedded in `app/pilot/store.py` defines the customer control database.
- HTML/CSS generated by Streamlit views and `app/pilot/exports.py`; TOML in `.streamlit/config.toml` configures the UI.

## Runtime

**Environment:**
- Streamlit processes run the internal and customer interfaces (`app/main.py`, `app/customer_main.py`).
- A separate Python supervisor launches isolated job processes (`app/pilot_worker.py`, `app/pilot_task.py`).
- Persistent local disk is part of the execution model (`app/pilot/store.py`, `app/retrieval/embeddings.py`).

**Package Manager:**
- pip requirements files: `requirements.txt`, `requirements-customer.txt`, and `openrouter_support/requirements-openrouter.txt`.
- No dependency lockfile or `pyproject.toml` detected in the repository scan.

## Key Dependencies

**Critical:**
- `google-genai>=1.30`: Gemini embeddings and optional text/vision generation (`app/services/runtime.py`, `app/retrieval/embeddings.py`, `app/services/model_gateway.py`).
- `chromadb>=1.0,<2`: local persistent vector collections (`app/retrieval/embeddings.py`).
- `rank-bm25>=0.2.2`: lexical rankings combined with vector rankings using reciprocal-rank fusion (`app/retrieval/vector_store.py`).
- `sentence-transformers>=3`: retrieval reranking support (`app/retrieval/reranker.py`).
- `pdfplumber>=0.11`, `PyMuPDF>=1.24`, `pypdf>=5`, `Pillow>=10`: PDF text, tables, rendering, image handling, and input checks (`app/extraction/`, `app/pilot/store.py`).
- `google-cloud-vision>=3`: optional OCR provider (`app/extraction/ocr.py`).

**Infrastructure:**
- `python-dotenv>=1.0`: loads project environment configuration (`app/main.py`, `app/customer_main.py`, `app/pilot_worker.py`).
- `supabase>=2.28,<3`: customer identity SDK, declared in `requirements-customer.txt` and used in `app/pilot/auth.py`.
- `httpx>=0.28,<1` and `jsonschema>=4.23,<5` are declared in `openrouter_support/requirements-openrouter.txt`; the installed `app/services/model_gateway.py` imports both directly. They are not explicitly declared in the primary requirements file.
- SQLite, `subprocess`, `contextvars`, and file locks use the Python standard library (`app/pilot/store.py`, `app/pilot_worker.py`, `app/services/observability.py`).

## Configuration

**Environment:**
- Project `.env` exists; its contents were not inspected. Runtime loads it with `override=False` (`app/services/runtime.py`, `app/customer_main.py`).
- Internal UI copies selected provider settings from Streamlit secrets only when the environment does not define them (`app/main.py`).
- Supabase settings resolve environment variables before Streamlit secrets (`app/pilot/auth.py`).
- Worker provider keys must be in its environment or project `.env`; it does not load the browser process's Streamlit secrets (`app/pilot_worker.py`, `docs/CUSTOMER_SETUP.md`).
- Key names and integration boundaries are documented in `INTEGRATIONS.md`; never copy secret values into planning files.

**Build:**
- `.streamlit/config.toml` sets theme and a 10 MB Streamlit upload limit. It also retains legacy OIDC placeholder configuration; active customer authentication is Supabase in `app/pilot/auth.py`.
- No compiled application build artifact is required by the documented launch commands (`README.md`, `docs/CUSTOMER_SETUP.md`).

## Platform Requirements

**Development:**
- Run commands from `multimodal-claim-verifier/`, the repository root; the parent folder contains a separate environment and other assets.
- Install the appropriate requirements and use `streamlit run app/main.py` for internal workflows (`README.md`).
- Use `streamlit run app/customer_main.py` plus `python app/pilot_worker.py` for customer workflows (`docs/CUSTOMER_SETUP.md`).

**Production:**
- The current customer design needs a persistent host, SQLite control database, workspace disk, and a supervised single worker (`app/pilot/store.py`, `app/pilot_worker.py`).
- Windows and POSIX worker locks have separate implementations in `app/pilot_worker.py`.
- No deployment platform is established by repository configuration; deployment readiness is a separate concern (`DEPLOYMENT_REVIEW.md`, `docs/CUSTOMER_SETUP.md`).
